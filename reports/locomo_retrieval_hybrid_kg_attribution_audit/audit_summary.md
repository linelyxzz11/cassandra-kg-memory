# Baseline Consistency Audit

## 1. Root Cause: Global vs Sample-Scoped BM25/Dense Discrepancy

The strong hybrid run used embeddings-based Dense ranking computed from scratch
inside the sample scope. The canonical sample-scoped results (from
sample_scoped_retrieval_summary.csv) were derived from PRE-COMPUTED global
retrieval CSVs (locomo_dense_bge_results.csv, locomo_bm25_results.csv), then
filtered to same-sample.

Key difference:
- Canonical: global-pool ranking -> filter to same-sample top10 -> evaluate hits
- Hybrid run: sample-scoped ranking from scratch with embeddings -> evaluate hits

The ranking ORDER differs because Dense similarity scores shift when the
candidate pool changes from global (5882) to intra-sample (~200). The same
memory pair (query, memory) has the same cosine similarity, but the relative
ranking among top10 changes.

## 2. Canonical Results (pre-computed CSV, verified)
- Dense-bge canonical: R@1=0.3669 R@10=0.7110 MRR=0.4738
- BM25 canonical: R@1=0.2032 R@10=0.4552 MRR=0.2828

## 3. Correct Methodology
Use pre-computed CSVs (locomo_dense_bge_results.csv) as SOURCE OF TRUTH for
Dense/BM25 rankings. These were computed identically to the original experiments.
The hybrid RRF should use these pre-computed rankings, not recompute from
embeddings.

## 4. KG Prior Leakage: NO
has_KG is derived from locomo_kg_edges_spacy.csv, which was generated by
observation_to_kg_spacy.py BEFORE any retrieval experiments. The KG edges are
from conversation memory text (entity-relation triples), NOT from answer labels.
truth_hasKG_rate > nontruth_hasKG_rate is expected (KG naturally captures
salient evidence, which is why it helps retrieval), not leakage.

## 5. Can previous baselines be reproduced?
YES. All baselines are from pre-computed CSV files in results/:
- locomo_bm25_results.csv, locomo_dense_bge_results.csv
- sample_scoped_retrieval_summary.csv (aggregate)
- analysis_category_wise.csv (per-category)
The BGE embeddings were pre-computed once with user's API key and cached as .npy.

## 6. Verdict
- Strong hybrid run: INVALIDATE (used wrong ranking methodology)
- Fixed run: use pre-computed CSV rankings for Dense/BM25, then RRF on those
- Ready for fixed attribution rerun? YES
